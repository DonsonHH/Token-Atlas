# 本机请求计时：实现与验收

来自会话请求：在现有 Token Atlas 中保留可核查的请求计时，验证 ccusage 能力并评估 GitHub 方案。运行时不得依赖已安装的 CC Switch、其数据库或转发代理。

- 用量和参考价取自 ccusage 的离线报告或外部汇总。原生 DSH 已纳入 ccusage；项目不再单独读 DSH 日志、不补算价格。计时不改变用量，也不推断账单。
- 仅从本机 Codex 日志读取计时。按完成日期、时区筛选，兼容有效的压缩历史。Codex 日志重放、重复完成、同一次完成的两种日志表达均不得重复产生样本。
- 「≈ 输出速度」是符合门槛样本的总输出 ÷ 总耗时，含首字等待；「≈ 首字」是见到有效输出证据的请求中位数。只有请求级证据可进入这些指标；回合级计时和代理实测不是同一口径。缺证据显示空值，部分覆盖用简短标签提示。
- 概览只陈列用量和模型分布；分析用页签分开趋势及请求性能。本机模型性能和近期请求是同一张卡片的两种明细。选择全部 Agent 时也只报告 Codex；选择 DSH、其他 Agent 或外部设备时不发起计时请求。
- 请求性能页签可见时每约 60 秒读取新记录，后台或离开该页签时暂停。Codex 按范围有界分批读取；达到上限时标为部分覆盖，不做高频全历史预热。相同范围共用工作。自动刷新静默，手动刷新只更新当前视图，沿用同一个 Sonner 通知组件；切换范围不显示上一个范围的计时。
- 桌面快捷方式启动一个生产服务器，构建只在缺失或源码更新时运行；不常驻开发编译进程。功能回归之外，需验证压缩解码限额、并发合并、缓存容量及生产进程空闲资源。

测试边界沿用现有日志夹具、HTTP 范围和工作区 UI：原始日志 → 公开计时报告验证匹配和缺失条件；并行请求和浏览器验证刷新、显示与隔离。不会运行真实模型请求或修改本机日志。
