# 原生日志方案：请求计数、速度和首字

核对日期：2026-11-23。目标是在 Token Atlas 的概览和用量分析里补充本机请求性能，直接读应用自己写出的记录。CC Switch 截图用来理解页面组织和指标含义；它的软件、数据库、同步任务和代理均不是依赖。

## ccusage 能提供什么

GitHub Releases 与 npm `latest` 同为 [ccusage 20.0.51](https://github.com/ccusage/ccusage/releases/tag/v20.0.51)。本机项目内 CLI 的 `--version`、`codex --help`、`codex daily --help` 和顶层命令列表与源码相符。它可用 `--json --offline --since --until --timezone` 输出所选范围的 token、价格与模型拆分；统一报表的 `--sections` 是 daily/weekly/monthly/session，并不是逐请求 trace。Codex 会话报表的 `lastActivity` 只是会话最近活动时间，不是某次请求结束、首字或总耗时，模型用量也不能反推请求数。见 [20.0.51 的 Codex JSON 结构](https://github.com/ccusage/ccusage/blob/v20.0.51/rust/adapters/codex/src/report.rs#L55-L145)。

正式版 20.0.51 未包含 DSH 命令；检查时 [上游主线 c1e6f559 的 DSH 适配器](https://github.com/ccusage/ccusage/blob/c1e6f55968d7baef590b6cfbe55d4bb3c3b1642d/rust/adapters/dsh/README.md) 仍未发布。它支持 DSH 不同日志代次、帧式压缩、分叉去重，并将部分 attempt / compaction 也纳入用量；[会话 JSON 快照](https://github.com/ccusage/ccusage/blob/c1e6f55968d7baef590b6cfbe55d4bb3c3b1642d/rust/adapters/dsh/src/snapshots/ccusage_adapter_dsh__report__tests__focused_dsh_session_json.snap) 和 [日报快照](https://github.com/ccusage/ccusage/blob/c1e6f55968d7baef590b6cfbe55d4bb3c3b1642d/rust/adapters/dsh/src/snapshots/ccusage_adapter_dsh__report__tests__focused_dsh_daily_json.snap) 都没有逐请求计时。直接替换当前 DSH 读取器不会获得首字，还会改变用量范围；将其与当前 DSH 读取器同时算进总量会重复。建议保留已验证的用量和定价路径，把性能作为独立的原生日志补充字段。

## 可复用的原生证据

### DeepSeek Harness（DSH）

- 官方 [SessionEvent](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/core/session/src/types.ts#L512-L528) 的时间是 Unix **毫秒**。`step/start` 开启 `(turn, step)` 对应的一次模型调用和其后工具执行；`assistant/message` 在同坐标记录模型消息、流和已报告用量。用该消息提交时间减步骤起点作为**估算**请求耗时，不取包含工具执行的 `step/end`。有 `llm/retry-started` 时以这条**等待之后**的事件重置同坐标的起点。见 [事件定义](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/core/session/src/types.ts#L313-L370)及[重试生产端](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/llm/llm-retry/src/index.ts#L185-L190)。
- `assistant/message.data.stream` 把文本、推理、工具调用增量压成带 `time0` 的连续片段；单个原始 `chunk` 有 `time`。最早有效输出时间减匹配起点可估算首字。原始流还有只报告用量、结束和块边界的记录；不能把一个纯用量或完成事件当作出现了首字。CC Switch 参考算法直接取最早流事件时间，这个更宽松的量具体代表的是**首个已记录流事件**而非用户看见的第一个字符。见 [官方流记录结构](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/llm/llm/src/assistant-stream.ts#L14-L49)、[流事件分类](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/llm/llm/src/types.ts#L496-L508)和 [CC Switch 对照](https://github.com/farion1231/cc-switch/blob/v4.0.39/src-tauri/src/services/session_usage_dsh.rs#L563-L608)。
- DSH 每个会话只选最高代次，支持 v3/v4；遇到未支持的最高代次应报告覆盖不足，不偷偷回退旧代。对 `session.v<N>.jsonl.zstd` 按连接的 Zstandard 帧解码，只采用已提交的完整记录。分叉只在最后一个带 `inherited: true` 的 `session/end-seed` 丢弃继承记录和计时状态，普通恢复不得清空本会话数据；继承段内的起点不能供本会话的请求使用。完结消息以其 ID 去重，解析支线时不可按会话文件重复计量。没有匹配起点、时间无效、失败或中断的尝试不应获得时长样本；性能采集不重算当前费用。见 [v3 归档定义](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/docs/persistence-changes/historical-formats/v3.md#L34-L44)、[v3 → v4 继承迁移](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/session/session-format-v3-to-v4/README.md)、[压缩容器](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/session/session-persistence-jsonl/src/zstd.ts#L1-L44)。

### OpenAI Codex

- 原生文件位于 `CODEX_HOME` 的 `sessions/` 和 `archived_sessions/`，有普通 JSONL 与 `.jsonl.zst`。相同 rollout 的活跃／归档或压缩／未压缩副本只能用一份；同一线程的不同 continuation 可能各有独立的新记录，不能仅按 thread ID 去掉全部续页。新分叉用 ordinal / 历史基准表明拥有范围；旧分叉复制的父前缀应匹配父记录，缺乏边界证据时宁可不发布性能样本。见 [Codex 压缩读取](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/rollout/src/compression.rs#L63-L81)、[文件名身份](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/rollout/src/rollout_file_name.rs#L10-L19)、[分叉边界](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/rollout/src/metadata.rs#L126-L152)及 [ccusage 的父前缀处理](https://github.com/ccusage/ccusage/blob/v20.0.51/rust/adapters/codex/src/replay.rs#L96-L181)。
- 现代 `token_usage_record` 包含一条完成响应的 `response_id` 和该次 `usage`，不是会话累计值；`event_msg.token_count.info` 可同时有 `last_token_usage` 和 `total_token_usage`，也可能完全缺少 `info`。同一请求的两份观察只能算一遍，重报累计值不算新请求。配对优先使用已知响应/线程身份、顺序和用量证据，不跨会话把恰好相同的请求当副本；不要把旧累计值当成本次输出。压缩、取消或中断时，有些 token_usage_record 可能没有匹配的非零 token_count，不应盲目加总或失去所有覆盖说明。参见 [Codex 协议定义](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/protocol/src/protocol.rs#L2578-L2679)与 [Tokscale 的双记录对账](https://github.com/junhoyeo/tokscale/blob/b265e836c58f085f50a836525aa60b8d45bd8d57/crates/tokscale-core/src/sessions/codex.rs#L411-L459)。
- `item_completed.payload.started_at_ms`（可选，Unix 毫秒）提供 reasoning 或 assistant message 的首个可用生成锚点。它不是所有版本都保存：Codex rollout 的现代 paginated 策略保留更多完成项，legacy 可只有旧 `response_item`/时间边界。以最近的可靠请求边界（turn context、用户发出消息、上一次请求结算、工具结果）估算起点，从第一条本次模型输出开始冻结；后续开发者／工具事件不应推迟开始。优先采用与当前请求配对的 `token_usage_record` 时间结算。如果旧 token_count 与后续工具结果同批写入，旧记录时间包含工具等待，宜使用可信最后输出锚点或留空。开始新轮次与取消要重置状态，同一刷新批次的迟到输出不能归入下一请求。仅具备请求结束和首个 **已知** 输出时才展示首字。见 [Codex ItemCompleted 契约](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/protocol/src/protocol.rs#L2227-L2244)、[保存策略](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/rollout/src/policy.rs#L127-L156)、[CC Switch 基于事件的计时参考](https://github.com/farion1231/cc-switch/blob/v4.0.39/src-tauri/src/services/session_usage_codex.rs#L319-L463)。

## 建议的呈现和验收

- KPI 可显示本机已观察的请求数、输出速度和首字中位数，分析页用同一范围按模型比较。速度估算为 `Σ合格样本输出 token ÷ Σ合格样本从起点到结算耗时（秒）`，与单请求速度取平均不是一回事。参考上游过滤短样本（输出少于 200 token、用时少于 1 秒），首字只用可靠窗口内的样本，两项分开计样本数并标记 `≈`。没有样本的日期、Agent 或外部导入留空；不将本机观察范围描述成所有设备、所有服务的网络性能。[参考显示规则](https://github.com/farion1231/cc-switch/blob/v4.0.39/src/components/usage/format.ts#L314-L382)
- 保留现有会话、用量、价格和导入语义。性能记录单独采样或聚合，不把 token 写回日报。文件读取只在本机、自然日按统一时区，JSON/UI 不输出消息正文、绝对路径、服务凭据。采用前台约 60 秒静默刷新，隐藏暂停，回到前台补读；耗时请求不能叠发。热力图、日趋势可以直接使用现有日报，不需要请求级数据库。
- 最少用合成普通／压缩日志验证：计数重复与分叉、请求跨日与筛选、工具结束后补写、开始缺失／无输出／取消与重试、包内首条时间、首次／空样本、原计费不受影响、隐藏页与恢复可见。实机仅比较 token/时间指标聚合与覆盖数，不把局部覆盖宣称为完整遥测。
