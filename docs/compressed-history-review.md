# 压缩日志兼容复查

## 原因

项目固定的 ccusage 20.0.30 只读取普通 Codex JSONL。2026-10-22 排查时，本机有 495 个 `.jsonl.zst` 压缩日志，分别位于 `sessions/` 与 `archived_sessions/`；旧读取器跳过这些文件，没有提示历史覆盖不完整。

上游从 [20.0.33](https://github.com/ccusage/ccusage/releases/tag/v20.0.33) 起支持 Zstandard 压缩日志。本次网页与 Jetson 导出脚本同步固定为已完成实际对照的 [20.0.40](https://github.com/ccusage/ccusage/releases/tag/v20.0.40)，保持离线读取，不手动解压或改写原日志。

## 复现与验证范围

- 升级前，当前读取器在同一批实际日志中只读到约 2.67B token、36 个活跃日；临时新版读到约 8.38B、121 个活跃日，7 月约 1.97B 用量重新出现。实时会话持续增长，因此这些数字是诊断时的快照。
- 最小样本为仅含模型上下文和 token_count 的合成日志：普通文件为 120 token，压缩后旧版为 0，新版仍为 120。没有复制或提交真实会话正文。
- 仓库增加实际调用已安装 ccusage 的集成测试，不只检查界面或版本号：普通、压缩、归档日志，重复副本去重，自定义日期，以及日、周、月、模型、会话汇总一致性。
- 合成压缩样本内嵌于测试，可在项目既有 Node.js 版本下运行；不需要系统 zstd 命令，也不依赖 Node 实验性压缩接口。
- Jetson 脚本与依赖版本一致性纳入自动检查。外部旧汇总仍需在原设备重新导出，本机刷新不能补出漏读的外部数据。

本次修改不扩大日志扫描到备份目录，不合并历史副本，也不修改 Codex 原始文件。

## 实现后复查

- `pnpm verify` 全部通过：lint、严格类型检查、31 项回归测试及生产构建。新增测试覆盖专用 Codex 报告和网页使用的 unified daily/session 报告。
- 新读取器在当前网页服务中生效，数据源页面显示 20.0.40。浏览器概览与导出实测为 8,389,997,825 token、121 个活跃日，覆盖 2026-05-16 至 2026-10-22；这是执行时的快照，不是固定示例数据。
- 实际接口返回的日、周、月、会话总量相等，7 月为 1,971,268,310 token，无数据提示；历史曲线已重新出现。浏览器没有控制台错误，导出包含相同历史与读取器版本。
- 重复副本测试使用不同事件，确保去重结果不是相同事件恰好被过滤的假阳性；活动压缩文件会优先于同路径旧归档普通文件。
- Jetson 脚本通过 Bash 语法检查与“已安装旧版、没有 pnpm、回退到 npx”的模拟测试；没有在实际 Jetson 上执行。
- 私人设备文件没有进入 Git 或生产部署追踪清单。验证截图与下载保留在 `C:/tmp/token-atlas-history-audit-20261022/`，不提交真实报告或会话内容。
